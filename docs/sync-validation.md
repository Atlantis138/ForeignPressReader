# 局域网同步审计与验证清单

> 当前源码已追加 Sync Model v4。新版阅读数据、解析补全和分页预览见 [阅读契约 v4](reader-data-v4.md)；下方早期 v3 检查记录保留为历史证据。真实双端 LAN 与厂商设备矩阵仍需另行验收。

## 1. 当前契约

同步是用户主动发起的单向 `A → B` 推送，不是后台双向镜像：

- 批次中同一稳定 ID 的可变记录采用发送端状态，接收端独有记录不会因为“发送端不存在”而被删除。
- 复习与强化历史等不可变事件按稳定事件 ID 合并；相同 ID、不同内容会拒绝整个批次。
- 刊物、分类、学习计划及其他可删除数据使用显式墓碑。全局/逐词进度重置以时间截断旧卡片和事件，防止旧设备把已重置进度带回来。
- 批次、缺失刊物包与回执可安全重试；逻辑数据、刊物恢复和接收游标在事务边界内提交。
- 活动学习 session、临时队列不跨设备复制，但接收计划删除或进度重置时会清理本机失效队列并结束空 session。

## 2. 数据覆盖矩阵

| 数据族 | 当前同步行为 | 接收后的本机处理 |
|---|---|---|
| 刊物内容与生命周期 | 只传缺失的规范化 `.fprpub`；存在/删除使用墓碑 | 校验清单、哈希、路径及内容 ID 后恢复；删除时清理正式刊物数据 |
| 阅读位置 | 按刊物稳定 ID 发送锚点和回退滚动值 | 恢复曾删除的刊物时强制随刊物重发，避免级联删除后位置缺失 |
| 分类、自定义刊名、归类 | v3 为每个分类/刊物覆盖建立独立记录和墓碑；旧 `library.management` 仅作本机 UI/备份镜像，不进入 LAN 批次 | 保留接收端独有分类及刊名；分类删除会解除相关归类但不抹掉独立刊名 |
| 阅读外观 | 只投影主题、字号、行距、纸张暖度 | 保留接收端栏宽等设备布局设置 |
| 语音偏好 | 投影语言、语速、自动发音、逻辑供应商及非密钥设置 | 保留接收端系统声音 ID 等设备能力，并刷新运行中语音上下文 |
| 翻译、词典、学习偏好 | 同步不含密钥的完整逻辑设置 | API 密钥仍由各设备密钥存储独立保管 |
| 用户词汇 | 词条快照、来源及取消墓碑、例句、收藏语境 | 按稳定 ID 合并并刷新词典/学习数据 |
| 学习计划 | 计划、来源、词源成员、逐词排除及删除墓碑 | 删除计划时清除接收端仍在等待/已揭示的本地队列项 |
| 学习进度 | scheduler profile、卡片、复习/强化事件、暂停、全局及逐词重置 | 先应用重置截断，再合并有效状态；清理不再被事件引用的 profile |
| 书库视图、排序、当前筛选 | 不参与设备推送 | 保留接收设备自己的界面状态 |
| 原始 EPUB、数据库/WAL、缓存、词典索引 | 不同步 | 各设备独立维护；必要刊物资源已包含在规范化包中 |
| API 密钥、TLS 私钥、设备身份、信任及 peer 游标 | 永不同步 | 每台设备独立生成并安全保存 |

## 3. 版本与兼容边界

| 契约 | 当前写出 | 读取/升级 |
|---|---:|---|
| SQLite schema | migration 3 | 从正式 v1/v2 顺序升级；失败时整次迁移回滚 |
| `.fprbackup` | format v3 | 接受 format v2 并转换书库细粒度记录；拒绝 format v1、Demo v5–v7 和未知高版本 |
| Sync Model | v3 | 保留 v2 冻结向量和接收映射；v1 仅保留既有内部恢复映射 |
| LAN Wire | v2 | Wire 形状不变，当前发现和发送声明 Model v3；真实局域网同步应使用同一当前版本的两端 |
| 内容 ID | v2 | 不改写，TypeScript/Rust 共用冻结向量 |

## 4. 自动化验证范围

仓库测试覆盖：

- 每一种非刊物逻辑记录族的双库往返及 A→B→C 传播。
- 计划删除、全局/逐词重置、临时队列清理和重复应用幂等。
- 接收端独有分类/刊名、分类墓碑、同名分类裁决及未来时间戳传播。
- 刊物删除、重新恢复、缺失内容包协商及阅读位置依赖重发。
- format v2 → v3 备份恢复、v1/v2 → v3 数据库升级和注入失败回滚。
- TypeScript/Rust 的 schema、Sync Model、Wire、内容 ID 与刊物包兼容向量。
- 批次数量、revision、重复 ID、哈希、媒体类型、路径穿越和未知版本等恶意输入。
- Windows/Android 接收完成后的缓存失效、设置刷新及移动深层路由回收。

```powershell
pnpm typecheck

pnpm test
pnpm test:interop
cd src-tauri
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test --all-targets
```

## 5. Windows ↔ Android 人工测试清单

测试前先各自创建 `.fprbackup`，确认两端均来自包含 migration/model v3 的同一代码版本。除断线场景外，两端保持“跨设备同步”页在前台。

### A. 首传、空增量与反向发送

- [ ] Windows 新建一项可辨认的数据：一本测试刊物、阅读位置、分类/自定义刊名、生词及学习计划；执行 Windows → Android，核对预览数量和全部结果。
- [ ] 不修改任何数据再次发送，核对没有重复刊物、重复事件或额外业务变化。
- [ ] Android 分别修改阅读位置、一个逻辑偏好和一个生词状态；执行 Android → Windows，核对运行中的 Windows 界面无需重启即可刷新。

### B. 学习计划与进度破坏性变化

- [ ] 先把同一计划同步到 Android，在 Android 打开“今日学习”并停留于该计划的等待卡片或计划详情页。
- [ ] Windows 删除该计划（先测试“不重置关联单词进度”），再 Windows → Android；Android 应退出失效深层页、可继续操作，已删除计划不再出现，旧卡片不能继续提交，界面不得卡死。
- [ ] 重建测试计划并产生一张复习卡；Windows 执行“删除计划并重置关联单词进度”，同步后核对 Android 对应卡片、事件及队列均不复活。
- [ ] Windows 执行全局学习进度重置并同步；Android 当前 session 应被安全结束/清理，dashboard 数字立即刷新，随后可正常新建学习 session。

### C. 书库细粒度冲突与墓碑

- [ ] 两端各建一个对方没有的分类，再单向发送；接收端应同时保留两个分类。
- [ ] Android 给一本仅 Android 拥有的刊物设置自定义刊名，并归入来自 Windows 的分类；Windows 删除该分类后发送。Android 应解除归类但保留刊物及自定义刊名。
- [ ] 两端离线创建同名但不同 ID 的分类后互发；两项都应保留并得到稳定、可区分的显示名，后续重传结果不再变化。
- [ ] 清空某本刊物的自定义刊名和归类后发送；另一端旧覆盖应被墓碑清除，而不是因发送端字段缺席继续保留。

### D. 刊物、位置与用户设置

- [ ] 同步一本带图片的刊物并打开到文章中部；接收端核对正文、资源和稳定阅读锚点。
- [ ] 接收端删除该刊物，再由仍保留刊物的一端发送；刊物和此前发送端阅读位置都应恢复。
- [ ] 从发送端删除刊物并发送；接收端刊物消失，重复发送不报错。随后重新导入同内容再发送，刊物可恢复且不出现两个副本。
- [ ] 分别修改主题/字号/行距、翻译/词典/学习偏好及语音速度后发送；核对逻辑设置刷新，同时接收端栏宽、系统声音选择和 API 密钥保持不变。

### E. 可靠性、安全与多设备

- [ ] 在批次传输阶段取消或断开 Wi-Fi，重新进入同步页并重试；正式数据不得出现半本刊物或已推进但未应用的游标。
- [ ] 在接收确认后、发送端收到回执前断网，再重试同一批次；结果应幂等且不会重复事件。
- [ ] 撤销信任后尝试发送；必须要求重新配对，证书或设备身份变化不得静默接受。
- [ ] 使用 A→B→C 顺序传播一次计划删除、分类删除和复习事件，再从 C 回传；显式墓碑与事件都不得丢失或复活。
- [ ] 在 Android 拒绝附近设备/局域网相关权限，或使用启用 AP isolation 的网络；同步页应给出可操作错误，本地阅读、学习和便携备份仍正常。
- [ ] 用一份当前 format v2 便携备份在 v3 应用中预览并恢复；书库分类/刊名、词汇和学习数据完整，重复恢复无额外变化。

记录异常时保留：发送方向、两端应用版本、预览计数、停留页面、失败阶段、是否重试成功，以及脱敏诊断。不要附带 EPUB 正文、API 密钥、证书私钥或完整设备 ID。
